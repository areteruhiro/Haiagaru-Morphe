# 自動巡回の5分・10分間隔（1.8.11）

対応: ChMate 191 dev／226 dev／242 dev。

ChMate標準の「設定 → 巡回・自動スレ検索」の巡回間隔に「5分」「10分」を追加します。「しない」や15分以上の項目もそのまま選べます。

標準の周期予約生成時にはWorkManagerの汎用ビルダーが15分未満を15分へ補正します。このパッチはChMateの自動巡回予約だけに限定して、その直後のWorkSpecの間隔と実行可能範囲を300,000／600,000ミリ秒へ補正します。初回の待機時間も選択した分数を使う標準処理を維持します。ほかのWorkManagerタスクやアプリ全体の最小間隔は変更しません。

実行は引き続きChMate標準のWorkManager経由です。巡回対象、通信条件、停止設定、再起動後の予約復帰、失敗時の再試行は標準処理に従います。Androidの省電力・Doze・バックグラウンド制限や通信条件により遅れる場合があり、秒単位の定刻動作を保証する機能ではありません。短い間隔では通信量・電池消費が増えます。

検証（2026-10-17）:

- 設定リスト・値の対応・翻訳別リソース・不明な配列の拒否など21項目に合格。
- 191／226／242のパッチ適用、資源再構築・署名済みAPK生成に成功。
- エミュレータへ3版をインストールし、各版38項目（計114項目）に合格。ネイティブのWorkSpecで初回と次回の時刻、5分・10分・既存間隔、ほかのビルダーの15分下限を確認しました。
- 実際の標準予約でも191は間隔・実行範囲・初回待機が各300,000ms、242は各600,000msでデータベースに登録されました。
- 実時間検証（時刻変更・ジョブ強制実行なし）では、242の10分予約は14:53:44の登録から15:04:08に標準のAutoCheckWorkが正常完了し、次の600,000ms予約が作られました。予定より約24秒遅れており、厳密な定刻実行ではありません。
- 191の5分予約は14:58:23以降、JobScheduler上で全条件を満たす実行可能状態になりましたが、15:05時点ではOSの実行待ちでした。5分ごとの自然起動まで確認済みとは扱いません。実時間検証は空の検証用アプリで行い、掲示板の通信を含む巡回結果は対象外です。

検証環境:

- 元の `Haiagaru_Root_API36` はデータを保持。既存ディスクの拡張はファイルシステムのエラーにより中止し、拡張前の状態へ復旧しました。
- 別環境 `Haiagaru_Test_API36_16GiB` を新規作成し、Android 16の初回起動と `/data` の16GiBを確認。191／226／242の検証用APKをインストールし、191の起動を確認しました。PCキーボード入力とソフトキーボード併用を有効にしています。

# ワッチョイ下4桁のNG登録

対象: ChMate 0.8.10.191 dev / 226 dev / 241 / 242 dev。

- 通常タップ: 下4桁のNGName追加ダイアログを開く。
- 有効、文字列／正規表現、連鎖、非表示、登録板をその場で選択する。
- 文字列では `-aabb` を新規登録する。
- 正規表現では新規登録または同じ板・有効／連鎖／非表示設定の既存行への追記を選ぶ。
- 追記は各条件を非キャプチャグループに包み、末尾の空の選択肢を保存しない。
- 長押し: `-aabb|` をコピーし、従来のNGName編集画面を開く。

## 検証

- `VerifyWacchoiSuffixNg`: 保存フラグ、記号のエスケープ、正規表現の結合。
- `VerifyWacchoiSuffixLongPress`: 通常タップと長押しの分離、無関係な項目のフォールバック、226の5引数形式、241の7引数形式、デフォルト引数マスク、非公開メソッド。
- `VerifyWacchoiSuffixHooks`: パッチ済みAPKのネイティブ行・Composeフック検査。
- API 36エミュレータの検証専用226/241で、実際の登録ダイアログの表示と保存を確認。文字列は flags=25（文字列・連鎖・非表示）、正規表現は flags=32、板androidで確認。
- 両版で既存の正規表現行への追記後、登録行数が増えず、その行の式が更新されることを確認。
- 両版でパッチ済みのネイティブclickableから長押しコールバックが生成され、実行するとNG編集画面へ遷移することを確認。
- 実際の226/242のメニューでは、ChMateのdismiss用ラッパーが元のコールバックを包んでいた。キャプチャされた項目を含む最大3段・24オブジェクトの範囲だけ確認し、元のNG用コールバックを認識するよう修正。回帰テストにラッパー付きコールバックを追加。
- 修正版226/242では、実際のスレのワッチョイメニューをADBで長押ししてNGName編集画面へ遷移することを確認。226の通常タップは引き続きNGName追加ダイアログを表示。
- 191/242も登録ダイアログの保存フラグと既存正規表現行への追記を確認。191は本物のMenuItemとネイティブアダプター `o.m6f.getView` が返す行の `performLongClick` からNG編集画面への遷移を確認。
- 191のgetViewはp1（位置）を後半でView等に再利用するため、末尾でp1を参照する実装はVerifyErrorになった。元メソッドを変更せず別名にし、元の引数を保持するgetViewラッパーで行をバインドする方式に修正。修正版でネイティブアダプターの生成・描画とNG編集画面の表示を確認。

Fridaの `scripts/frida-ng-suffix-dialog.js` は検証専用パッケージに限定する。`showSuffix` は実際の画面を表示し、`saveFixtureDialog` は画面準備後に実際の選択部品と保存ボタンを操作する。公開済みリリース資産は更新していない。

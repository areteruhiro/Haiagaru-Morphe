# 既読スレをまとめて削除

対応: ChMate 0.8.10.191 dev／226 dev／242 dev。通常表示・タブレット表示で利用します。

以下は1.8.14の仕様です。1.8.13は「未読0件」のスレだけを対象にしていましたが、要望に合わせ「一度読んだスレ（未読レスが残っていても対象）」へ変更しています。1.8.13の公開ファイルは差し替えていません。

## 開き方

開発版では、Haiagaru設定の「スレを読む → 更新ボタン長押しで既読スレを削除」でオン／オフを切り替えられます（初期オン・自動保存）。オフにしても、設定済みの削除ジェスチャーは利用できます。長押しのみ標準の処理へ戻り、更新の短押しには影響しません。公開済み1.8.14にはこの切り替えは含まれません。

- 板のスレ一覧の更新ボタンを長押しします。短押しは従来どおり更新です。
- またはChMateの「設定 → ジェスチャー」で「既読スレをすべて削除」に未使用のジェスチャーを割り当て、板のスレ一覧上で操作します。初期状態では未割り当てです。

## 確認と削除

1. 操作した板の一覧にある、一度読んだスレがチェック一覧に表示されます。未読レスが残っているスレも含み、未読件数を併記します。未閲覧のスレ、閲覧していないお気に入り・巡回取得だけのスレは候補に含めません。
2. 各行をタップしてチェック／解除します。「すべて選択／すべて解除」でも切り替えられます。
3. 「削除（件数）」を押すと、選択したスレの履歴と取得済みログをChMate標準の削除処理で削除します。キャンセルすると何も削除しません。

タブレット表示でも、別の板や右側のスレ本文の履歴をまとめて削除する動作ではありません。
削除直前に、同じスレの閲覧記録が残っており、操作した一覧にも存在することを再確認します。新着レスがあっても削除対象です。

削除は元に戻せません。必要なログは先にバックアップしてください。保存済みアーカイブやレス保存スレは対象にしません。
掲示板サーバー上のスレ自体は消えないため、板を更新すると未取得のスレとして再び表示されることがあります。

Haiagaru 1.8.13で追加しました。

## 検証状況

1.8.13公開時には191／226／242のパッチ済み検証アプリで、合成データを使った確認画面の13項目（個別チェック、全選択・解除、0件時の無効化、キャンセルなど）を確認しました。当時の選別ポリシー15項目と、各版の削除API・ジェスチャー・長押しの組み込みも検査しています。
実際の板一覧からジェスチャー／更新長押しを経由してログを削除する通し確認と、タブレットの左右ペインでの確認は未完了です。実データを削除した検証ではありません。

修正版では、一覧アダプターの内部リストではなく表示対象を取得し、ヘッダー付き一覧にも対応します。既読件数の古い一覧スナップショットだけで除外せず、DBの閲覧記録と照合します。再現用の検証DBはユーザーDBとは分離しています。

修正版の基本ポリシー13項目、226のネイティブ一覧アダプター＋分離したSQLite検証DBの13項目、確認画面などの実行時テスト16項目に合格しています。未読が残る既読スレの選択、未閲覧・隠れた行の除外、ヘッダー付き一覧、DB閲覧状態の再確認、未読606件の併記、個別／全件チェックとキャンセルを含みます。ユーザーの履歴・ログは削除していません。

226の更新／巡回ボタンが反応しなくなる件について、標準ツールバーが使い回す共用Viewに長押しリスナーを付けると、次のタップをそのViewが消費することを再現しました。修正版は共用Viewを変更せず、標準の長押しイベントを利用します。修正版APKを上書きしたエミュレータで、分離した標準ツールバーの10項目（旧処理でのタップ消失、修正方式での反復タップ、別ボタン、長押し、長押し後のタップなど）を確認しました。実際の通信を伴う巡回と実ログ削除の通し検証とは区別してください。

追加調査で191／242も同じ共用View構造であり、旧方式のリスナー登録によるタップ消失を両版の標準ツールバーで再現しました。全対応版で不要になった画面生成時の登録フックも削除しています。共通の回帰テストは `scripts/frida-toolbar-patrol-test.js`、標準APKの構造検査は `scripts/InspectPatrolToolbar.java` です。

191／226／242の標準ツールバーを使った分離テスト各11項目、計33項目が通過しました。3版とも最終APKへの上書き後にも同じ11項目が通過し、最終APKのバイトコード検査で標準長押しフックの存在・画面生成時の登録呼び出しがないこと・互換用bindが何もしないことを確認しています。ユーザーデータ削除や実際の通信巡回は実施していません。

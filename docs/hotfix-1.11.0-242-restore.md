# 1.11.0: 241のバックアップを242 devへ復元した後のクラッシュ

## 原因と修正

提供されたOPPO CPH2797 / Android API36のログは、`o.zzaW.c(o.KeJ11, boolean)` の `VerifyError`。命令位置 `0x101` で、整数になった `v13` を投稿オブジェクトとして追加のNG処理へ渡していた。

ネイティブ処理はNG判定結果をキャッシュへ書く前に、`p1` を投稿オブジェクトからレス番号へ、`p2` を祖先探索の引数からキャッシュへ再利用する。従来の投稿者ID連鎖フックは、この再利用の後から `p0..p2` を呼び出し引数として上書きしていた。

241/242/243では、レス番号のロードより前に投稿オブジェクトと判定値を個別に渡す形へ変更した。`p1` と `p2` をフックの作業領域に使わず、ネイティブのキャッシュ書き込みを維持する。191/226の専用経路は保持する。

この例外はバックアップの展開・形式変換のスタックではなく、復元後にスレを表示するNGエンジンの検証で発生している。修正のためにバックアップや復元済みデータを消去する必要はない。

## 確認結果（2026-10-20）

- API36 / `emulator-5554` の修正前242で、実際のネイティブメソッドを呼び出し、添付ログと同じ `0x101` / `v13 Integer → Object` のVerifyErrorを再現。`build/crash-hotfix-242-before-call.log`。
- 修正後242を同署名・同パッケージへ上書きし、ART上のNGエンジン生成とネイティブメソッド実行が通過。`build/crash-hotfix-242-runtime.log`。反射でメソッド一覧を読むだけでは再現確認にならないため、インスタンス割り当てと実メソッドの呼び出しを使用した。
- 共用端末での画面操作競合を避け、既存16GiB AVDをread-onlyで別起動したAPI36 / `emulator-5556` にも242/226を導入。242で初回案内を操作し、板一覧→家電製品→Android板→指定のHaiagaru Part2スレ（701レス）の本文を実画面で表示でき、新規クラッシュ記録がないことを確認。`build/crash-hotfix-242-thread5556.png`。
- 同じ242の実フィルターダイアログで画像をタップし、ダイアログを閉じずにチェックが表示され、背面のレス一覧も画像レスに絞り込まれることを確認。チェック前後は `build/crash-hotfix-filter242-before.png` と `build/crash-hotfix-filter242-after.png`。226の実プロセスでもチェック状態の初期値・オン・オフ・外部モデル反映の5項目が成功（`build/crash-hotfix-dialog226-runtime.log`）。
- 191/226/241/242/243の元APKへ本番フックを単独適用し、実引数・ネイティブのレス番号ロード順序・判定値の保存先・DEX生成を検査して5版すべて成功。`build/crash-hotfix-poster-hooks.log`。
- 統合MPPのAndroidビルド、191/226/242への適用・再構築・署名、エミュレータへの上書き導入に成功。191のスレ表示・226の画像表示・チェック状態の即時更新修正も同じ作業ツリーに含む。
- ユーザーのバックアップZIPそのもの、およびOPPO実機での復元通し確認は未実施。公開・リリース番号の変更も未実施。

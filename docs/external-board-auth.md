# 外部板のアプリ内認証

対応: 0.8.10.191 dev／0.8.10.226 dev／0.8.10.242 dev。

書き込み画面の「︙ → 外部板の認証ページ」、または「Haiagaru設定 → 詳細 → 外部板の認証ページを設定・開く」から開きます。

1. 板のURLと、その板が案内している認証URLを指定します。エッヂの `bbs.eddibb.cc` は `/auth-code` を候補として表示します。他の板では認証ページのURLを登録できます。
2. アプリ内のWebViewで認証コードなどを入力します。認証コードの発行・送信やログイン自体はサイト側の機能です。
3. サイト上で認証成功を確認し、「認証を反映して戻る」を押します。WebView Cookieをその板のHTTPS通信に連携します。
4. 書き込み内容を確認し、必要なら自分で再送信してください。二重投稿防止のため、自動再送信はしません。

書き込み画面で認証要求を含む標準エラー表示を検出すると、エラー全文を選択・コピーできる確認画面を表示します。「認証コード: …」の形式を判別できる場合は「認証コードをコピー」、それ以外は「エラー全文をコピー」を使えます。コピーしても画面は閉じません。内容を確認してから「認証ページ」で進んでください。コードの自動入力・投稿の自動再送信は行いません。検出できない表現・表示方式の場合は「︙」から開いてください。通常の投稿成功や、書き込み画面を閉じた後の別画面では自動案内しません。

## 安全性と制限

- URLはHTTPSのみ。証明書エラーは無視せず停止します。ユーザー名・パスワードを埋め込んだURLは使えません。
- 他のサイトへ移動する際は移動先のorigin（ホスト・ポート）を表示して確認します。HTTP・ファイル・intent等への移動は行いません。
- Cookie連携は「認証を反映して戻る」を押した板のHTTPS originに限定します。CookieManagerのパス・期限・Secure判定に従います。別サイト・別ポート・HTTP接続にCookieを渡しません。
- ネイティブ通信側のCookie更新も、連携したoriginに限ってWebViewへ反映します。既存のChMate Cookie保存処理は維持します。
- Cookie・認証コード・パスワードを検証ログへ出力しません。フォーム値をアプリ独自に取得したり、JavaScriptインターフェースで読み出したりしません。
- 「連携を解除」はCookie連携と登録URLを解除します。WebViewに保存されたサイトのログイン状態そのものを削除する操作ではありません。
- Cookie以外の専用トークン、端末・アプリ・User-Agentに固定された認証、WebViewを禁止するサイトなどは、この汎用連携だけでは対応できない場合があります。全サイトの認証成功を保証する機能ではありません。
- この認証機能は板の名前・URLやログの保存先を変更しません。登録済み外部板の編集機能とは独立しています。

## 開発時の検証

- HTTPS URL検証、origin分離、認証要求の検出、同一originの候補URL抽出について、`scripts/VerifyBoardAuthRules.java` で24項目を確認。
- Cookie連携テストは隔離した検証アプリとダミーCookieを使用します。実アカウントのCookie・認証コードは出力しません。
- 191／226／242へのパッチ適用に成功。各版の標準CookieJarで、OFF・明示許可・別origin拒否・HTTP拒否・パス制限・サーバー側Cookie更新・連携解除の7項目を確認。
- 242の更新後APKで、検証用のネイティブ例外から認証案内とURL確認ダイアログが開くことを確認。実際のUIタップでアプリ内認証Activityへ移動し、指定サイトを表示できることをスクリーンショットで確認。
- 指定サイトはCloudflare確認画面を表示。本人操作が必要な確認・認証コード入力・認証後の実投稿は未確認です。合成エラーの検証を、実サイトでの投稿エラー再現や認証成功と同一視しないでください。

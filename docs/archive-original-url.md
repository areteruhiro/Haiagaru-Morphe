# スレアーカイブの元URL（1.8.11）

191 dev／226 dev／242 dev向け。

## 開き方

ChMateのアーカイブ一覧上部の「アーカイブの元スレURLを確認」、またはHaiagaru設定の「過去ログ・エッヂ検索 → アーカイブの元スレURLを確認」から保存先を選択します。

- 元スレURLを選択可能なテキストで表示し、「元URLをコピー」でコピーできます。
- 保存先のローカルファイルURLも併記します。通常のアーカイブの開き方・DAT／IDX・標準URL表示は変更しません。
- 今後、アプリ内で取得・表示したスレをアーカイブする際に、ChMateのスレ情報から生成したHTTP(S) URLを記録します。本文中のリンクから元URLを推測することはありません。
- 保存時の元URLを記録していない既存アーカイブは、保存名にホスト名・板・スレ番号がすべて含まれ、一致を確認できた場合だけ復元したURLを表示します。復元時はHTTPSを使用し、保存時と同一である保証がない旨を表示します。
- 特に5chのアーカイブは板IDにサーバー名が含まれない場合があります。その場合は`mi.5ch.io`等を勝手に補いません。「記録がありません」と表示し、「元URLを登録・修正」から手動登録できます。
- ファイル一覧はフォルダごと・100件ごとに表示。本文を読み込んだり、元サイトへ自動アクセスしたりしません。

## バックアップ

元URLはアプリ内部の`haiagaru-archive-origins`へ、アーカイブ内の相対DATパスをキーとしたJSONとして保存します。元のDAT／IDXへは書き込みません。

MEGA／ローカルバックアップの「スレのアーカイブ」を選択すると、アーカイブ本体と元URL情報の両方を含みます。既存のMEGA送信・復元処理と同じZIPバックアップ経路を使います。ファイルURLの絶対パスやパッケージ名を記録のキーにしないため、別端末・別パッケージに復元しても対応するアーカイブから元URLを参照できます。復元後もローカルに残るDATのパスはその端末のものです。

元URL情報を含む新しいバックアップの復元には、この機能に対応したパッチを使用してください。古いパッチは未知のZIP領域を安全のため拒否する場合があります。

## 検証

- `:patches:buildAndroid`成功。
- `VerifyArchiveOriginPaths`の15項目成功。HTTP(S)・5ch／Talk／したらばのURL、保存名からの復元、不明サーバーの推測禁止、パストラバーサル拒否を確認。
- 191／226／242へパッチ適用成功。`VerifyArchiveOriginHooks`で各版のネイティブアーカイブ作成処理（DAT／IDXコピー後）、スレ情報のURL観測、設定／アーカイブ一覧の2つの入口、MEGA共通ZIP処理への接続を確認。
- 専用191エミュレータアプリで`frida-archive-origins-test.js`の12項目成功。実際のBBSUrlInfoから得た元URLを保存し、隔離した合成バックアップの作成・復元後に同一URLを取得できることを確認。ローカルファイルとして開く動作が維持されること、手動登録、不明サーバーの推測禁止も確認。
- 191で元URL選択画面からDATを選び、元URL・保存先・登録修正／コピーのボタンが実画面に表示されることをUI階層で確認。
- MEGAサーバーへの実送信・実復元は行っていません。226／242の実画面通し確認は未実施（226検証APKの上書きはエミュレータ容量不足で失敗）。既存ユーザーデータは削除していません。

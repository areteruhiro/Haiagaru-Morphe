# 画像・動画のアップロード先

対応: ChMate 191 dev／226 dev／242 dev。Haiagaru本体パッチに含まれます。

「Haiagaru設定 → 画像・動画・X／Twitter → 画像・動画のアップロード先」、または
書き込み画面の「︙ → アップロード先を変更」から設定します。
画像と動画を別々に指定できます。初期値は両方とも従来のImgurです。

| 送信先 | 対応 | 条件 |
| --- | --- | --- |
| Imgur（従来の設定） | 従来どおり | ログインアップロードは従来の開発中パッチが必要 |
| imgbox | JPEG／PNG／GIF | 1ファイル10MB以下、匿名Web送信。Family Safe／Adultを指定可能。固定の帯域幅上限なし（濫用時の制限あり）。保存した削除・管理リンクでアカウントなしの削除が可能 |
| imgpile | 画像・動画 | 公式FAQでは1ファイル97MB以下。Web送信はAPIキー・アカウント不要。既存のAPI送信も選択可能 |
| Sendvid（Web送信） | 動画 | APIキー・アカウント不要の公式Web画面。標準添付の自動送信先とは別操作。共有ページURLをコピーして使用 |

imgbox自身は動画を受け付けません。別サイトへの動画転送は行いません。
選択・縮小などはChMateの既存画面を使い、成功時に直接URLを本文へ挿入します。
通常のアップロード履歴にもURLが残ります。この2サイトの削除キーをImgurへ送ることはありません。
imgboxは匿名で新しいギャラリーを作成して送信します。

## サーバー削除・管理（未リリース）

標準の画像アップロード履歴の「︙ → imgbox／imgpileのサーバー削除・管理…」、または
アップロード先設定の同名ボタンから、対象を選んでサイトの管理ページをブラウザで開けます。

- この機能追加後に送信に成功し、管理情報が保存された画像・動画が対象です。新しい順に表示します。
- imgboxは送信時のトークンから専用管理URLを保存、imgpileは自分のアップロードのメディアページを保存します。
- 開くだけでは削除しません。サイト上で対象を確認し、削除を実行してください。imgpileは送信したアカウントへのログインが必要です。
- 自動一括削除は未対応です。サイト側の削除成功も自動判定しないため、ChMateの履歴は削除済みへ変更しません。
- 過去分・管理情報を取得できなかった画像は削除権限を復元できません。URLから削除キーを推測しません。
- imgboxの管理URLには削除権限があります。アプリ専用領域に保存し、一覧・ログへは表示しません。
  ローカル／MEGAバックアップでは「認証情報」を含めた場合に保存されます。バックアップは他人に渡さないでください。
- imgboxは現在、検証用画像の送信がHTTP 500となり、管理ページの取得もHTTP 500でした。
  実画像のサーバー削除成功は未確認です。imgpileの削除はWebの所有者操作で、公開APIの一括削除としては保証しません。

## imgpileのAPI不要Web送信（未リリース）

アップロード先設定の「imgpile Web送信・履歴／削除（API不要）」を開きます。
標準アップロード履歴の︙にある削除・管理画面からも開けます。
API送信先の選択やAPIキーの保存は不要です。Web送信は標準添付の自動送信先とは独立しています。

1. アプリ内の公式サイトで画像・動画を選択し、送信します。
2. 結果の画像・動画を開き、画面上の「URLをコピー」で直接URLを選択します。
3. 元の書き込み本文へ貼り付けてください。自動挿入や標準アップロード履歴への記録は行いません。

WebViewのCookieとサイトの履歴を保持します。同じ画面のサイト上で所有者操作を使って削除できます。
アプリデータ／Cookieを消去した場合やCookieが期限切れになった場合、匿名での削除権限を失う可能性があります。
外部ブラウザにはCookieを渡しません。API送信分の管理ページは引き続きアカウントでのログインが必要です。
Web送信分のCookie／サイト履歴はMEGA等への移行を保証しません。
削除はサイト上の利用者操作のみで、アプリが自動送信・自動削除することはありません。

imgpileは合法かつ成人の同意があるNSFWコンテンツを明示的に許可しています。規約・法令で禁止される内容は送信できません。
容量は「100MB」とは案内せず、現時点の公式FAQにある97MBを記載しています。
サイト変更やアクセス確認によりWebViewから利用できない場合があります。アクセス確認を回避する実装は行いません。

## SendvidのAPI不要Web送信（未リリース）

「Haiagaru設定 → 画像・動画・X／Twitter → 画像・動画のアップロード先」、または
書き込み画面の「︙ → アップロード先を変更」から「Sendvid 動画Web送信（API不要）」を押します。

1. アプリ内の公式サイトのUPLOADから、動画を選択して送信します。
2. 送信結果の動画ページを開き、上部の「URLをコピー」で共有用URLを選択します。
3. 元の書き込み画面へ戻り、本文へ貼り付けます。

- コピーするのは`https://sendvid.com/動画ID`の共有ページURLです。MP4直接URLではありません。
- APIキーは使いません。通常の画像添付ボタンからの自動送信、本文への自動挿入、標準アップロード履歴への記録は未対応です。
- Cookieはアプリ内WebViewに保持します。外部ブラウザや他の送信先には渡しません。
- 匿名投稿の削除には、送信時にサイトが提供する削除リンクが必要です。サイト上で別途保存してください。
  アプリは削除リンクの自動保存・自動削除を行わず、共有URLのコピー候補にも含めません。
- 公式FAQでは90日間連続で閲覧されない動画は削除される場合があります。永続保存用途には向きません。
- 現時点の公開アップロード画面では上限設定が`1000 × 1024 × 1024`バイトですが、
  サイト側の変更や個別条件があるため、アプリ内では容量の保証をせずサイトの判定に従います。
- ファイル選択では利用者が選んだ動画だけを渡します。別サイトへのページ移動、HTTP／証明書エラーの接続は許可しません。
  API・アクセス確認の回避は行いません。Google等の外部認証画面への遷移も現時点では対象外です。
- 191 dev／226 dev／242 dev共通のWeb送信画面です。実サイトへの動画送信・削除の通し確認は未完了です。

確認元: [Sendvid](https://sendvid.com/)、[公式FAQ](https://sendvid.com/help/faq)、公開アップロードスクリプト（2026-10-17）。

## imgpileのAPI送信の準備

1. [imgpileのSettings](https://imgpile.com/settings)で自分のAPIキーを発行します。
2. 上記のアップロード先設定に入力し、画像または動画でimgpileを選んで保存します。
3. ChMateの通常の画像添付操作から送信します。

APIキーをチャット・不具合報告・スクリーンショットへ載せないでください。
キーはアプリ内に保存します。アプリの設定ファイルを含むバックアップにはキーが入る場合があるため、
バックアップの共有には注意してください。不要になったキーはサイトで失効してください。

[公式API説明](https://imgpile.com/developers)によると、無料プランは1日500件までです。
静止画は変換・縮小される場合があり、保存期限など各プランの条件が適用されます。
返された直接URLをそのまま使い、`processing: true`があってもポーリングしません。
ImgurのログインCookieや他サービスの認証情報は送信しません。

## 失敗時と制限

- 勝手に他の送信先へ切り替えず、自動再送しません。タイムアウト時も送信済みの可能性があるため、再送前にサイトを確認してください。
- HTTPリダイレクトには追従せず、APIキーやファイルを別ホストへ転送しません。
- imgboxは公開Webフォームを使う非公式な連携です。サイト変更・通信制限により利用できなくなる場合があります。
- 形式・容量・APIキーを事前検査します。各サイト側の追加制限や投稿可否までは保証しません。
- 検証用HTTP応答による画像／動画プロトコル・エラー・認証情報の分離テスト69項目と、管理URL・削除先の分離検査31項目を確認しました（実削除なし）。
- imgboxの実サイトで、フォーム取得・セッションCookie・送信用トークン取得まで確認しました。数値のタイムゾーンを持つCookie期限への対応を含みます。
- 2026-10-17、利用者の許可を得てPCとAndroidエミュレータで生成PNGの送信を検証しました。
  エミュレータの191では、実際に組み込んだ送信ラッパーをFridaから呼び出し、64×64・239バイトのPNGを1回送信しました。
  フォーム取得・トークン取得はHTTP 200、`/upload/process`はHTTP 500でした。送信成功・画像URL取得は確認できていません。
  自動再送・他サイトへの転送はせず、検証用の一時ファイルを削除し、変更した送信先設定を復元しています。画像選択画面から本文挿入までの通し確認は未完了です。
- imgpileのAPI送信には利用者自身のAPIキー設定が必要です。Web送信には不要です。
- Web送信先の事前検査では`/uploads/init`がHTTP 403のJavaScript／Cookieによるアクセス確認になりました。
  このため自動HTTP送信は追加せず、公式Web画面を利用者が操作する方式としました。WebViewでの実送信・匿名削除の通し確認は未完了です。

# スレ順キーワード・4桁検索履歴削除

## 242 devのスレ順キーワード

242標準のThreadListViewModel内で、登録キーワードを供給するコルーチンが `sortId == 200` の場合にnullを返していた。「スレ順」でのみキーワードグループが作られない原因。

242限定で、この比較分岐だけを無効化する。空リスト処理・sortIndexが2以上の場合の扱い・勢い／新しいの比較器・ネイティブのマッチ処理・NG処理は変更しない。対象コルーチンと分岐の形を検証し、一致しなければパッチ適用を失敗させる。191／226には変更を加えない。

検証: ビルド成功、242元APKへのパッチ適用成功。`VerifyThreadKeyword242.java` により公式元APK・修正済みAPKをそれぞれ実機の独立プロセスで実行し、4ソートID×4 sortIndex×空／非空の32ケースずつを確認。実データのスレ一覧での表示確認は未実施。

## 上／下4桁検索履歴

検索画面 →「上・下4桁の検索履歴・保存結果」から操作。

- 「チェックして削除する履歴を選択」をオンにし、履歴をタップして複数選択。「選択を削除」で確認後に削除。
- 「履歴を全削除」は絞り込み条件にかかわらず上下両方の全履歴・保存結果を削除。確認ダイアログに明記。
- 検索用ページキャッシュは削除しない。
- 検索による絞り込み後もIDで選択を維持し、非表示の選択があることを表示。
- 削除した実行中セッションの遅延保存による履歴復活を防ぐ。未選択セッションの保存や、削除後の新規検索保存は維持。
- 削除対象は専用履歴ディレクトリ内のUUID名JSONのみ。削除失敗数を通知する。

検証: `VerifyWacchoiHistoryDelete.java` の合成データ9ケースを実機上で確認。実ユーザーの履歴は削除していない。新しいチェック一覧の実画面確認は未実施。

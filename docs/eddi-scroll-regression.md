# エッヂ過去ログ検索スクロールの回帰確認

2026-10-20 / API36 x86_64 / emulator-5554 / 226 dev。

## 原因と修正

汎用Compose変換では外側の画面スクロールと内側ScrollViewが重なり、nativeのweight指定も失われていた。結果欄とページ送りが重なる状態を実画面で確認。検索専用の有限高さのレイアウトへ変更し、結果ScrollViewだけに残り高さを配分する。詳細条件のフォームは別領域でスクロールする。

結果カードはLinearLayoutへクリックリスナーを付けているが、変換先が子TextViewだけを描画しクリックを落としていた。ViewGroupのクリック／長押しをComposeへ引き継ぐ。

横画面では固定操作とフォームで高さを使い切るため、表示設定をTopAppBarへ移し、フォーム最大高を40%に制限。状態行・元サイトボタンを小さくし、結果領域を確保する。入力欄上の説明文を入力欄ラベルへ誤変換しない。

## 実行済み

- 修正前226に `scripts/frida-eddi-scroll-fixture.js` で実パーサーを通した50件を表示。複数回縦スワイプ後も01〜09のまま。
- 初回修正版226では縦スワイプで03〜06へ移動し、最終47〜50まで到達。
- 詳細条件の開閉中にも結果領域を保持。
- 結果タップでChMateのResListActivityへ移動し、指定スレ658レスを表示。戻ると42〜45の元位置を保持。
- 658の画像をImagesViewer2Activityで表示し、同PIDのcrash bufferは空。
- 横画面で結果欄が消える問題を追加発見し、最終レイアウトを修正。
- 最終版の横画面でも結果行の描画を画像確認。最終ビルドは通常Lint込みで成功（build/eddi-scroll-final-build.log、5分54秒）。

検索先への接続は10秒のconnect timeout。実サーバーから検索成功したとは扱わない。共有の画面処理につき191／242の重複した実操作確認はユーザー指示で省略。報告端末Samsungや接続していない実機で確認済みとは扱わない。

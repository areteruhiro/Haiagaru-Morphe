# 242 HOME更新時のキーワード並びを保持

## 原因

通常のHOME表示は登録キーワードを渡して標準ソーターを呼ぶが、HomeViewModelの更新通知側2か所では最終引数にnullを渡していた。標準ソーターはキーワードの有無で並び順の選択肢を変えるため、同じsortId=102／sortIndex=0が「スレ（キーワード）」から「スレ（★）」へ変わる。

## 修正

242のソーター単位で直近のキーワード一覧を保持し、更新通知側2か所だけ不足した引数を補う。通常のキーワード編集経路から渡されたnullは「登録なし」としてキャッシュを破棄し、削除したキーワードを復活させない。空リストも有効な更新として扱う。

並び順番号の加減算、巡回対象の変更、ユーザー設定の書換えは行わない。191／226は対象外。ソーターの所有者は弱参照で保持し、別のHOMEインスタンスへ状態を流用しない。

## 検証

`VerifyHomeRefreshKeywords.java` で繰り返し更新・設定編集・全削除・nullへの変更・別インスタンス・入力リストの変更など19ケースを確認。ビルド・パッチ適用結果は作業報告と区別し、実画面の通し確認済みとはしない。

最終版のビルドと242元APKへの適用に成功。`VerifyHomeRefreshHooks.java` で最終APK内の更新通知2か所がキーワード復元結果をネイティブソーターへ渡すこと、通常経路の設定変更記録が1か所にあることを確認する。端末へのインストールと実画面での更新確認は未実施。

# 個人NGの収集と共有配信（設計案・2026-10-28）

ユーザー指定: 初回同意後、既存の個人NGもまとめて送信する。以後の追加・変更も候補として送信し、運営側でフィルターする。現時点では設計であり、この自動送信は未実装・未稼働。

## 収集

初回は送信対象カテゴリ、対象件数、送信先、送る値を表示して同意を得る。同意後の初回スナップショットから既存NGを分割送信し、その後はNGストアの正常保存後の差分をキューへ入れる。起動時の差分照合で取りこぼしを回収する。表示処理からNG一覧を全走査しない。

対象候補はNGID・NGName（ワッチョイやトリップを含む）・NGWord。同意画面で種類ごとに選択可能。送信するのは種類、値、板指定、正規表現/一致方法など適用に必要な設定、操作種別と候補ID。Cookie・認証トークン・閲覧履歴・書き込み履歴・ローカルパス・元レス全文は送信しない。高度NGのJavaScriptは個人NG同期とは別扱いで送信しない。

日付/板が不明な過去のNGIDを現在日付や現在板に勝手に割り当てない。元の登録日時と実際の投稿日を区別し、対象期間不明として審査待ちへ送る。全板NGは全板指定として保存し、端末の開いている板で補完しない。ワッチョイ全文/上4桁/下4桁/正規表現を混同しない。

重複判定はインストール単位のランダムID＋正規化した条件ID＋操作ID。再送しても二重加票しない。端末識別は本人確認ではなく、複数インストールによる票増しを完全には防げない。

## 運営側

GAS受付は受理した候補を専用Inboxへ保存。Pendingは既存実装で書込ジャーナルに使用しているため審査待ち用途へ転用しない。未審査候補をRulesやGitHubへ直接流さない。

状態は審査待ち/採用/保留/却下。種類・板・期間・対象範囲・重複・過度に広い表現を検査する。票数は参考値に留め、古いID/期間不明/短い一般語/広範な正規表現等は自動採用しない。氏名や連絡先などが含まれる候補は公開前に除外できる。

元の個人NG削除は、その利用者の報告取消として扱う。他利用者の報告や承認済み条件を一方的に削除しない。承認済みの配信停止は別の管理操作とし、次回配信へ反映する。

## 配信と端末適用

承認済みのデータだけGitHubへJSONとして出力。F9判定スクリプト配信とは形式・保存領域を分け、共有NGデータからコードを実行しない。全体版番号/全件置換/配信停止/生成時刻を持たせ、途中失敗では旧スナップショットを維持する。

受信条件は個人NGストアへ登録せず別キャッシュに保管して表示判定へ合成する。受信・復元・条件統合が新規ユーザー登録として再送されないよう由来を区別する。共有受信ON/OFF、個人NG送信ON/OFF、対象種類、判定強度、個別解除は独立。送信OFF時は未送信キューも止める。送信済み候補の削除申請と端末内解除は別操作。

## 実装順

1. 未統合の共有NG9コミットを現在のNG境界と比較し、3版の非表示/解除/再起動復元を検証。
2. 初回同意と既存NGプレビュー、由来識別、キューの保存/重複/取消を実装。
3. GASのInbox・審査・採用/却下を追加し、専用テスト板で往復確認。
4. GitHubのデータ配信、配信停止、個人NGとの独立を検証。

既存公開GASの設定/シート/データはこの設計検討では変更しない。実ユーザーNGの送信も行わない。

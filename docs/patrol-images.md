# 巡回時の画像自動保存

対応: ChMate 0.8.10.191 dev／0.8.10.226 dev／0.8.10.242 dev。

Haiagaru設定 → 画像・動画・X／Twitter →「巡回時の画像自動保存（スレタイ・URL指定）」で設定します。初期OFFです。

- スレタイのキーワードを1行に1つ登録します。いずれかに部分一致すれば対象になります。
- スレURLも複数登録できます。タイトルまたはURLのどちらかが一致すれば対象になります。レス番号やl50付きの5ch／Talkリンクもスレ単位で扱います。
- 母集団はChMate標準の巡回対象です。「スレタイ・URLで巡回対象を絞り込む」をオフにすると巡回対象全体、オンにするとフィルター一致のスレだけが対象です。初期は絞り込みオンで、条件未登録なら画像を取得しません。
- 保存先は「ChMateの画像キャッシュ」または「Download/Haiagaru/スレごとのフォルダ」を選択できます。
- ChMate標準の起動時・手動・定期巡回で、画面を開かずに画像を取得します。画像自動保存がオンで、絞り込み条件が登録されているか絞り込みがオフの場合、「本文(dat)もダウンロード」がオフでもその巡回の本文取得を有効にします。ChMateの設定値は変更しません。画像自動保存がオフ／条件未登録なら標準動作を維持します。
- 本文は巡回対象全体の更新判定に従って取得し、画像保存の段階でスレタイ・URLを絞り込みます。画像だけでなく本文の通信量も増える場合があります。巡回対象を増やしたり、独自の定期巡回を開始したりはしません。
- キャッシュは標準の画像取得・管理処理を使用します。正常なキャッシュがあれば再ダウンロードしません。容量制限による消去後は再取得されます。
- 公開フォルダはスレ単位で分離し、URLのハッシュによるファイル名で重複を避けます。画像が削除されている場合は再保存します。失敗したファイルは保存済みとして扱いません。
- Android 10以上ではMediaStoreを使用します。Android 6～9では共有ストレージへの書き込み権限が必要です。
- 動画は対象外です。通信量・使用容量が増えます。既存の画像取得設定や通信保護は引き続き有効です。取得失敗時に直接通信へ切り替える処理は追加していません。
- 巡回を長時間占有しないよう、画像待機は1件30秒・1スレ合計2分までです。未取得分は次に本文を取得する巡回で再試行します。OFFにすると新規取得とコピーを停止しますが、すでにChMateに渡した通信は完了する場合があります。

本文の取得を行わない巡回、更新がなく本文取得が省略されるスレ、終了・巡回対象外のスレについては、この機能だけで新たに本文を取得しません。

## 開発時の確認範囲

- 起動時・通常巡回への拡張（1.8.13）：191／226／242のパッチ適用とDEX検査で、巡回共通メソッド先頭の本文取得フラグとDAT後の画像保存コールバックを確認。242のエミュレータでは設定を復元するテストで48通りのオン／オフ・条件・標準本文取得フラグを確認しました。この変更後の実際の起動時巡回／手動巡回を通したHTTP取得は未検証です。
- キーワード・URL照合、絞り込みオン／オフ、画像URL判定、保存名について21項目のテストを実施。
- 191／226／242の元APKに対し、巡回のDAT取得呼び出しと画像キャッシュの結合を検証してパッチ適用成功。
- 226のエミュレータ検証では合成した未表示レスとローカルHTTP画像を使用し、OFF・不一致では取得せず、一致時に標準キャッシュへ保存し、再実行と公開フォルダへのコピーでもHTTP取得が1回だけであることを確認。
- 191もキャッシュ結果オブジェクトの引数なしコンストラクタに対応後、OFF・不一致・標準キャッシュ・再実行・スレ別フォルダ・公開保存・再保存の7項目を確認。
- 242でもOFF・不一致・標準キャッシュ・再実行・スレ別フォルダ・公開保存・再保存の7項目を確認。同じ画像へのHTTP取得は1回。検証で、242のURL取得先が空配列のstatic accessorになっている問題を検出し、本文の標準URL抽出＋Haiagaru添付補完を行う専用メソッドへ修正。
- 242の隔離検証アプリで、Androidの登録済み定期ジョブ → PeriodicAutoCheckWork → AutoCheckWork → subject.txt → DAT → PatrolImages → 標準画像キャッシュの通し確認を実施。スレを画面に開かず、PNG先頭バイト137をキャッシュから読み出せることを確認。再巡回後も画像HTTP取得は1回（subject 3回／DAT 2回／画像1回）。
- 上記通し確認はAPI 36エミュレータとローカルHTTPのテスト板を使用。検証アプリのWorkSpec予定時刻を前倒しし、JobSchedulerから登録済みジョブを実行。本文取得対象は標準の再取得フラグ（state bit 2）で指定。WorkerやonThreadの直接呼び出し、DAT結果の差し替えは行っていません。HTTPの例外はFridaでループバックの検証接続に限定し、製品のHTTPSポリシーは維持。
- 自然な15分経過・実サイトの新着数判定・Doze中の実行時刻・実端末での長時間運用は、この通し確認の対象外です。FridaのWorker監視が再帰して落ちた試行は成功判定から除外しています。

# 未読・履歴・スレのDAT落ち非表示（1.9.0）

## 開発版の追加修正・下書き／送信済み

Haiagaru設定 → **スレを読む → 画面と操作**で次の設定を個別に変更できます。設定検索からもオン／オフできます。

- 未読・履歴・スレのタブでDAT落ちスレを非表示：従来の設定。
- **DAT落ちスレの下書きを非表示**：HOMEの「下書き／送信済み」にある未送信の下書きへ適用。初期オフ。
- **DAT落ちスレの送信済み・書き込み先を非表示**：同じタブの送信済み本文と「書き込んだスレ」へ適用。初期オフ。

本文・送信履歴・DATは削除しません。各設定をオフにすると保存データを再表示します。新規スレ作成の下書き、DAT落ちと確認できない書き込み先は残します。ネイティブのDAT落ち状態が確認できるスレを優先し、5chでは公式の過去ログ表示も非同期に確認します。空になった下書き／送信済みの見出しも表示から除きます。

191の最終表示用リストは`j`ですが、従来の補正は`g`・`i`だけを対象にしていました。また、並び替え後の更新・Filter.publishResultsが未加工リストを再設定する経路がありました。191の3つのリストを補正し、191／226の最終Adapter通知境界で再除外するよう変更。タブを離れた際は対象モードも更新し、対象外タブの内容・検索順序を維持します。242は既存のAdapterData生成時フィルタを使います。

標準表示設定のDAT落ち項目は「既読スレを上に」をテンプレートにし、文字のピクセルサイズ・字体・色・チェック欄・余白を統一しました。

実機XIG05（730eae72）の191で設定オンにもかかわらず40件中9件がネイティブDAT落ちだった状態を再現。修正ロジックを一時ロードして31件／DAT落ち0件、遅延した一覧更新の再除外、検索順維持、対象外の送信履歴への非干渉、元データ保持と文字スタイル6項目を確認しました（`build/dat-drop-regression/device.log`）。これは修正APKのインストール完了や、226／242の実機確認を示すものではありません。

ChMate標準の表示設定で「既読スレを上に」の近くに「DAT落ちスレを非表示（未読・履歴・スレ）」を追加。191はViewのチェック欄、226は直接Compose、242はチェック行モデルへ追加する。Haiagaruの表示設定にある同項目と `hideDroppedHomeThreads` を共有する。初期オフ。

対象はHOMEの未読（101）・スレ（102）・履歴（103）。標準のDAT落ち状態bit 1だけを判定し、表示コピーから除く。書き込み履歴や他のタブを変更しない。DB・DAT・未読情報の削除は行わない。設定変更後は対象タブを開き直す。オフで元の保存データを再表示する。

DAT判定フィールドは191 `o.onAdDisplayed$setIcon.o`、226 `o.Yy2$open.l`、242 `o.getAvailabilityStatus$r8lambdawJ5MHcSJed_CjC7r4OWD0UxyJsQ.l`。ネイティブDAT落ちラベルの表示条件と照合。合成39チェックが成功したが、全版の実画面でのオン／オフ・一覧復帰は未確認。

標準表示設定への追加と動画サムネイル別プロセスのFirebase初期化補正は、現在実機へインストールされている検証アプリより新しい変更。ビルド成功／実機確認／公開は別々に扱う。1.8.16は引き続き公開取り下げ状態。

# 通常版ChMateからエッヂのCookieを移行（開発中）

Haiagaru設定の「通信・詳しい設定」に「通常版ChMateからエッヂのCookieを移行」を追加。
通常版アプリの改造・アンインストール・root・証明書の追加を必要とせず、
同じ端末の通常版がHTTPプロキシに送ったCookieヘッダーを明示的に受け取る。
取得できることは通常版の通信方式とCookieの属性に依存する。

## 方法の比較

| 方法 | 判断 |
|---|---|
| 標準ZIP・Androidバックアップ | 調査した242 devではclient_cookies.xmlが対象外 |
| ADB・Shizukuによる内部ファイル読取 | 通常のshell権限では不可 |
| Webサイト | 別アプリ・別ドメインのCookieは読めない |
| HTTPSの復号プロキシ | 通常版の証明書信頼設定に依存し、今回は実装しない |
| IOMateのようなローカルHTTPプロキシ | 通常版がHTTPで送るCookieを受け取れる可能性がある |
| 移行専用のローカル受信 | 採用。上流へ転送せず、元アプリのCookieを更新する応答も返さない |

IOMateのREADME・ProxyServer.kt・HttpRequest.ktを調査した。HTTPヘッダーを解析する方式を参考にした独立実装で、同プロジェクトのコードは転用していない。
参照: https://github.com/kitadai31/IOMate

## 操作

1. Haiagaruでエッヂの板を一度開き、通常のCookie保存先を初期化する。
2. 認証画面と並行通信を閉じ、設定から移行を開始する。
3. 通常版のProxy設定を控え、表示された `127.0.0.1:ポート番号` に設定する。
4. 通常版でエッヂの板かスレを更新する。受信側は503を返すので通信エラーになる。
5. Haiagaruへ戻り、受信したCookieの名前と保存条件を確認して移植する。
6. 成功・失敗・キャンセルにかかわらず通常版のProxy設定を元に戻す。

待受はIPv4ループバックの動的ポートのみ、最大5分・1回の受信。
他端末からの接続は受け付けない。アプリがOSに終了された場合は受信をやり直す。
Cookie値や投稿本文を画面・ログ・クリップボード・受信ファイルへ出さない。
POSTを受けてもヘッダーの終端までしか読み取らず、どのリクエストも外部へ送らない。
HTTPS CONNECT、対象外ホスト・パス、不正・重複ヘッダー、過大な入力を拒否する。
HTTP CookieにSecure属性等により元々含まれない値は取得できない。
本機能から投稿操作を促さず、認証・投稿の自動実行も行わない。

## 保存

対象ホストは `bbs.eddibb.cc`、板別保存先は `/liveedge/` 固定。
Cloudflareの `cf_clearance` と `__cf*` は閲覧ブラウザの別認証として除外する。
countsession/securitykeyは片方欠落・空値・大文字小文字違いの重複を拒否する。

Cookieヘッダーから元のDomain・Path・有効期限・HttpOnly等は復元できない。
受信した値は同一ホスト限定、Path=/、期限を捏造しないセッションCookieとして扱い、
この明示的な移行に限り再起動後もネイティブの既存シリアライザーで保存する。
同名の既存Cookieは対象URLで取得できる旧Pathを失効させてから置換する。
他ホストや別名のCookieは残す。板別Cookieが有効ならネイティブ共通保存先は変更せず、
エッヂの板別保存先だけを更新し、進行中リクエストの旧世代書戻しを無効化する。
Haiagaruの認証情報バックアップを明示的に有効にした場合、この保存済みCookieも対象になる。
サイト側で失効したCookieや接続元に結び付いた認証を有効に戻す機能ではない。

## 検証

`scripts/EdgeCookieReceiverTest.java`: 模擬Cookieのみを使い、ホスト/パス/ヘッダー検査、
認証ペア、Cloudflare除外、POST本文の非読取、実際のループバック受信・503応答、
終了時の受信データ破棄を検査。外部サイト・実アカウント・投稿は使用しない。
通常版242 devに保存された実Cookieの移行成功は、まだ確認していない。

2026-11-14: 受信側の28項目が成功。Androidエミュレーターの新規隔離テストアプリで、
未改造191 dev・226 dev・242 devのCookieライブラリをそれぞれ読み込み、
通常保存ではセッションCookieが永続化されないこと、明示保存後のjar再作成で値が一致すること、
失効後には読めなくなることを確認した（`EdgeCookiePersistenceInstrumentation.java`）。
利用者のアプリやCookieは読み取っていない。Java/Kotlinコンパイル成功。
WindowsでのMPP生成はメモリ不足で失敗したため、専用のGitHub Actionsで最終生成を行う。

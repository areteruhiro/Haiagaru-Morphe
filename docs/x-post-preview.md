Android上でネイティブと同じsetText→onBoundを模したビューを使用し、キャッシュ済み・未取得・全文・折りたたみ開閉・行再利用・無効化・例外後の復帰を含む50チェックを確認しました。外部通信や実投稿を行わない分離テストです。

Haiagaru設定の「X／Twitterの投稿内容をレス内に表示（追加通信あり）」をオンにします。初期状態はオフです。
191 dev／226 dev／242 devのスレ画面で、投稿URLのあるレスに投稿者名・ユーザー名・本文・日時・投稿へのリンクを追記表示します。
画像・動画は既存の「URLメディア」の取得設定に従ってサムネイル表示します。
スクリーンショットのWeb埋め込みそのものではなく、テーマに合わせたネイティブの文字プレビューです。プロフィール画像やWeb埋め込み内の操作は含みません。

## 表示設定（1.8.11）

「Haiagaru設定 → 画像・動画・X／Twitter」から設定します。

### 端末内キャッシュ（1.8.11）

取得済みの投稿本文・投稿者・日時を端末内に保存し、アプリ再起動後やオフラインでの再表示にも利用します。保持期間は取得から7日（読むだけでは延長しません）、最大128投稿／16MiBです。上限を超えると古いものから削除します。取得失敗は永続保存しません。

同カテゴリの「X投稿プレビューのキャッシュを削除」から確認後に削除できます。次回表示時は再取得します。投稿の編集・削除前の内容が期限内は表示される場合があります。

Androidのキャッシュ領域を使うため、OSによって削除される場合があります。永久保存やMEGAバックアップの対象ではありません。画像・動画ファイルのキャッシュとは別です。期限付きメディアURLを古いまま使わないよう、画像・動画の取得経路ではこの永続キャッシュを使いません。

- **X投稿の本文を全文表示**：初期オン。取得元が公開している全文を表示します。オフでは冒頭140文字まで表示します。取得元に省略された本文しかない場合、全文を復元することはできません。
- **X投稿のプレビューをカード形式で表示**：初期オフ。Haiagaru設定の「X（Twitter）の投稿表示」で切り替えます。投稿者・アカウント名・本文・日時・投稿リンクを角丸の枠付きで表示し、明るい／暗い文字色に合わせて背景を切り替えます。従来の文章表示、全文表示、タップでの折りたたみを併用できます。191／226／242 dev対応。
- カードは軽量なAndroidネイティブ描画です。X公式埋め込みのWebViewではなく、プロフィール画像・認証バッジ・いいね数・返信一覧・フォロー操作の再現は行いません。カードを有効にするだけで追加の画像やWebページを取得することもありません。
- **X投稿のプレビューを折りたたむ（タップで開閉）**：初期オフ。オンでは「▶ X投稿のプレビューを表示」をタップすると展開し、「▼ X投稿のプレビューを閉じる」で再び折りたたみます。本文の取得は展開時に行います。画像・動画の自動取得は既存のURLメディア設定に従い、この設定では停止しません。
- 展開中の「投稿を開く」は元のX投稿を開きます。折りたたみ操作とは別です。開閉状態は表示行ごとの一時状態で、再起動などをまたぐ保存はしません。

取得失敗時は表示中の行に対して最大2回再試行します。再利用された行にも再適用し、キャッシュ済みのプレビューは行の計測前に反映します。非同期の取得・開閉で高さが変わる場合は、リストの位置を補正します。

- 公開メタデータをHTTPSで取得します。Xへのアクセスが発生するため、閲覧元のIPアドレスは取得先に伝わります。
- ログインセッション・認証情報は送信しません。非公開・削除済み・アクセス制限された投稿を取得できるとは限りません。
- 取得できない場合は元のURL表示を残します。WebViewや外部スクリプトは実行しません。
- 元のレス本文・DAT・NG判定データは書き換えません。オフにすると追加表示を取り除きます。
- 同じ投稿への通信は画像取得と共通化し、並列数・待ち行列・メモリキャッシュを制限します。
- 既存の画面内TextViewへの表示が対象です。元サイト表示・専用WebView・NGで隠れたレスには追加しません。
## 投稿への操作（開発中）

Haiagaru設定 → X（Twitter）の投稿表示 → 「Xプレビューに返信・リポスト・いいね・リンクコピーを表示」で有効化します（初期オフ）。従来表示とカード表示の両方で使用できます。

返信・リポスト・いいねはX公式の操作ページを開きます。実際の送信や確定はユーザーが行い、ログインを求められる場合があります。アプリが自動実行したり、操作済みの件数を表示したりはしません。「リンクをコピー」は元の投稿URLをクリップボードへコピーします。

「X投稿・操作をブラウザのアプリ内タブで開く」は初期オンです。Custom Tabs対応ブラウザではそのブラウザのログイン状態を利用でき、閉じる操作でスレへ戻れます。非対応ブラウザでは通常表示になります。独自WebViewに認証情報を預けず、HaiagaruはパスワードやブラウザのCookieを取得しません。ブラウザ・X側の制限により操作ページを利用できない場合があります。この設定をオフにすれば通常のURL起動に戻ります。

追加検証：191／226／242の検証アプリの隔離ローダーでAndroid表示テスト75項目、性能12項目、ListView位置保持4項目を確認。操作欄のオン／オフ、公式操作URL、Custom Tabs用Intent、コピー対象のURLを検証しています。実アカウントでの送信・いいね確定、ブラウザからの復帰、クリップボード貼り付けの通し操作は未検証です。

## 表示処理の軽量化（開発中）

191／226／242共通のプレビュー処理を改善しています。表示する内容やオン／オフ設定は変更しません。

- 同じ本文の投稿ID解析結果を再利用します。本文は最大128件相当・合計256K文字までの上限付きで保持し、Viewや描画済みSpanは解析キャッシュに保存しません。
- 内容・表示設定・開閉状態が変わらなければ、再結合時のプレビュー再生成とTextViewの本文再設定を省略します。
- 取得した投稿と無関係な行は再生成しません。複数の取得完了通知はまとめ、1回のUI処理では最大8行を扱います。再試行以外の通知では、内容が変わっていない行を書き直しません。
- 140文字の抜粋は解析時に作り、行の描画ごとの文字数計算を省きます。キャッシュ削除・破棄済みの待機リクエストは開始しません。

検証は実ネットワークやアカウントを使わないAndroid表示テストです。変更のない行を1,000回結合・レイアウト評価しても追加の本文再設定が0回であること、URL解析結果の再利用、関連行だけの更新、完了通知のまとめ処理などを確認します。`scripts/BuildXPostPreviewPerformance.ps1` と `scripts/x-post-preview/frida-performance.js` で再実行できます。ダウンロード自体の通信速度や実スレのスクロール性能を測定した値ではありません。

カード追加後は191／226／242の各検証アプリ上の隔離ローダーで、表示・開閉・明暗背景の描画・再入防止63項目、性能12項目、実ListViewの位置保持4項目と一時失敗後の再試行が通過しました。合成データを使ったテストで、実スレの読込・未読数や242の実RecyclerViewでの通し検証とは区別してください。拡張／パッチのビルドも成功しています。

# エッヂのレベルによる自動NG：調査と実装条件

2026-10-31。利用者要望：認証取得日を記録しHaiagaru間で共有、推定レベルの任意閾値以下を自動NG。別途レベル表示スレを自動クロールし、表示レベル5（変更可能）以下のIDも自動NG。

現状は調査段階。認証情報の収集・共有送信・自動クロール・NG追加はまだ実装/実行していない。確認した公開subject.txtは読み取りのみ（DAT一覧61行、レベル/認証/Lvを含む対象タイトルなし）。URL指定が必要で、タイトルだけで適当なスレを選ばない。

## 仕様確認待ち

- 対象のレベル表示スレURL。継続スレを追従する場合の選定条件。
- 「全Haiagaru」：共有に同意した全利用者か、自身の端末間か。
- 推定計算の想定。現在稼働中のエッヂのレベル仕様が不明なため、参考公開ソースの昇格条件を現行仕様として断定しない。

## 確認できたこと

- 参考実装 https://github.com/edginer/eddiner/blob/main/src/routes/bbs_cgi.rs は、前回昇格から23時間以上経過した投稿時にレベルを1加算し上限20。経過時間だけで自動昇格する実装ではない。認証日だけから実レベルを算出できない。
- https://github.com/edginer/eddiner/blob/main/src/tinker.rs に初期level=0、last_level_up_at=0。Tinkerには認証トークン自体も含まれる。Cookie/JWTの丸ごと共有は行わない。
- 認証完了時刻はサーバー側のAuthedCookie.authed_timeにある。公開された他人の投稿からその値を読めるAPIは今回のソース調査では確認できなかった。
- サーバー生成のレベル表示は名前欄の `</b>(L数値)<b>` または `</b>(L数値 識別文字列)<b>`。本文や任意の名前入力にある数字を実レベルと誤認しない必要がある。現在の稼働サービスのDATで形式確認が必要。
- Haiagaru側にはExternalBoardAuthActivity / BoardCookiesのCookie反映経路、native NGの表示用overlay、GAS共有NGの配信処理がある。これらを再利用する余地があるが、認証日と公開投稿IDの正確な対応付けは別途検証する必要がある。

## 推奨する分離

1. 認証を実際に確認した日時と、既存Cookieを初めて見た日時を分ける。後者を過去の認証日として扱わない。Cookie復元・移行でも根拠を失わない。
2. 日付からの推定と、公開スレで観測したレベルを別々の設定・閾値にする。実測がある場合はそちらを優先する。
3. IDはエッヂ内・投稿対象日単位で照合。他日・5ch/pinkなどへ持ち越さず、不明なIDを勝手にNGにしない。
4. 標準NGを大量登録する方式より表示用overlayを使い、OFFで解除でき、DAT/本文/履歴を変更しない構成にする。
5. 共有を追加する場合は既存の個人NG送信同意と区別して送信項目を明記する。認証Cookie、JWT、認証コード、IPアドレスを送信しない。自己申告の認証日を第三者IDの確定情報として無検証で配信しない。
6. 公開スレのクロールは許可されたエッヂホストに限定。増分取得、間隔の設定、429/503等での待機、上限を設ける。共有サーバーで取得をまとめられるなら利用者全員が同じスレを巡回する設計を避ける。

上記の確認後、クライアント側の初期OFF設定・閾値・除外、認証日記録、公開DAT解析、日付付き観測キャッシュ、共有サービスの受理/配信、native表示への適用を順に実装する。新機能の公開指示はまだない。

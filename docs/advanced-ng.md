## 1. 機能の概要

端末内のJavaScriptで、スレタイまたはレス本文をNGにする条件を追加する機能です。キーワード、正規表現、投稿者情報などを組み合わせられます。

設定場所は、ChMate設定 → Haiagaru →「高度なNGルール（条件・スクリプト）」です。全体の有効スイッチは初期状態でOFFです。全体と個別ルールの両方がONで、判定対象と対象板が一致する場合に実行します。

| 項目 | 仕様 |
| --- | --- |
| 判定対象 | スレタイ／レス本文。1ルールにつきどちらか一方 |
| 適用範囲 | すべての板／指定した板URL |
| 判定結果 | 関数が `true` を返すとNG、`false` を返すとそのルールではNGにしない |
| 複数ルール | OR判定。どれか1件が `true` ならNG |
| 複数条件のAND | 1つの関数内で `&&` などを使って記述 |
| スレタイの一致 | 判定したスレ一覧から対象行を除外 |
| レス本文の一致 | ChMateの標準NGWord判定フラグへ追加。最終表示は標準NG処理・表示設定に従う |
| 設定の保存 | 端末内。標準NGWord／NGIDの登録一覧へスクリプトを変換・追加する機能ではない |

`false` は「NGを解除する」という意味ではありません。別の高度なNGルールや標準NGに該当すれば、そちらの判定は残ります。

## 2. 設定と保存の手順

1. 「NG条件を追加」を押し、ひな形を選びます。
2. 条件の名前、個別の有効／無効、判定対象、適用板、判定式を入力します。
3. 必要に応じて「直近のデータでテスト」を実行します。
4. 「一覧に反映」でルール一覧へ戻ります。
5. 全体の「高度なNGルールを有効にする」をONにし、一覧画面の「保存」で確定します。

「一覧に反映」は編集中の一覧へ反映する操作です。端末への保存は一覧画面の「保存」で行います。ルールの削除も、一覧画面で保存して確定します。

ひな形は次の5種類です。

| ひな形 | 初期の判定対象・内容 |
| --- | --- |
| スレタイにキーワードを含む | スレタイ。`text.includes(...)` |
| レス本文にキーワードを含む | レス本文。`text.includes(...)` |
| 正規表現で判定する | スレタイ。`/正規表現/i.test(text)`。対象は編集で変更可能 |
| エッヂの記者IDで判定する | スレタイ。`options.posterId` の一致 |
| JavaScriptを最初から書く | スレタイ。常に `false` を返す初期式 |

保存によって判定キャッシュを破棄します。開いたままの一覧への即時反映は保証しないため、反映を確認するときは対象のスレ一覧やスレを開き直してください。

## 3. 板の指定

「すべての板に適用する」をOFFにすると、「適用する板のURL（1行に1つ）」を指定できます。指定した板と判定データの板が一致する場合だけ実行します。

- `https://example.com/board/` のような板URLを入力します。スレURLや板名だけの指定ではありません。
- URLのホスト名の大文字・小文字、末尾の `/`、HTTP／HTTPSの違いは比較時に正規化します。
- ホストとパスが判定の基準です。別サーバーへ移転した板は新しいURLも必要です。
- ユーザー情報、クエリ、フラグメント付きURLは設定できません。
- 板情報を取得できない場合があります。指定板ルールが適用されないときは、実際に開いた板URLを確認してください。

## 4. スクリプトの書式

関数全体を入力してください。

```javascript
function (text, options) {
  return text.includes("キーワード");
}
```

戻り値はBoolean型の `true` または `false` に限ります。文字列、数値、オブジェクト、戻り値なしはエラーです。非同期処理は使用しません。

`text` は、スレタイまたはHTMLから表示用テキストへ変換したレス本文です。スレタイ末尾から記者IDを抽出できた場合、その記者IDの表記はスレタイの判定文字列から取り除きます。

### `options` の項目

取得できない情報は `null`、空文字、または未設定になる場合があります。端末・版・読み込み経路により取得範囲が異なるため、存在を確認してから使ってください。

| 項目 | 内容 | 主な対象・注意点 |
| --- | --- | --- |
| `target` | `"title"` または `"body"` | 判定対象 |
| `boardUrl` | 板URL | 取得できない経路では内部の代替URLになる場合あり |
| `threadId` | スレッド番号 | 主にスレタイ。レス判定では原則 `null` |
| `createdAtMs` | スレ作成日時の推定値。Unix時間のミリ秒 | スレッド番号から算出できた場合 |
| `createdAt` | 上記を表すJavaScriptの `Date` | 算出できなければ `null` |
| `resCount` | 取得できたスレのレス数 | 主にスレタイ |
| `speed` | レス数と推定作成日時から計算した勢い。1日当たりのレス数 | 主にスレタイ。取得できなければ `null` |
| `posterId` | スレタイ末尾から抽出した記者ID | エッヂ等の記者ID。レス投稿者のIDとは別 |
| `responseNumber` | レス番号 | レス本文 |
| `responseId` | 判定するレス自身の投稿者ID | レス本文。NGIDの登録内容ではない |
| `threadTitle` | 取得できたスレタイ | レス本文。経路により空文字 |
| `name` | 名前欄の表示用テキスト | レス本文 |
| `mail` | メール欄 | レス本文 |
| `dateText` | 日時欄の文字列 | レス本文。`Date` 型ではない |

### 記述例

キーワードのいずれかを含む場合:

```javascript
function (text, options) {
  return text.includes("キーワードA") || text.includes("キーワードB");
}
```

本文と投稿者IDの両方が一致する場合（対象を「レス本文」に設定）:

```javascript
function (text, options) {
  return options.responseId === "対象ID" && text.includes("キーワード");
}
```

正規表現で判定する場合:

```javascript
function (text, options) {
  return /単語A|単語B/i.test(text);
}
```

レス数と勢いを組み合わせる場合（対象を「スレタイ」に設定）:

```javascript
function (text, options) {
  return options.resCount != null && options.speed != null
    && options.resCount < 20 && options.speed > 1000;
}
```

## 5. プレビューの仕様

「直近のデータでテスト」は、直近に取り込んだ判定用データへ、編集中の1ルールを適用します。対象を読み込んでいない場合は、先にスレ一覧またはスレを開くよう案内します。

結果は「取得済みデータの件数中、このルールがNGにする件数」です。全履歴・全スレの検索や、標準NGを含めた最終非表示件数ではありません。取得件数は版や読み込み経路で異なり、表示中のスレ全件を含むとは限りません。個別ルールがOFFなら一致件数は0件になります。

プレビュー自体は全体スイッチのON／OFFとは独立して実行できます。判定式を変更した後は、再度テストして一覧画面で保存してください。

## 6. 実行上限とエラー

Java／Android APIへアクセスできない、制限付きJavaScriptインタプリタで実行します。設定と判定対象を外部へ送信する処理はありません。

| 制限 | 現行実装 |
| --- | --- |
| ルール数 | 最大32件 |
| 1ルールのスクリプト長 | 最大32,768文字 |
| 1回に1ルールへ渡す判定データ | 最大6,000件 |
| 判定文字列の長さ | 1件につき最大131,072文字 |
| 1ルールの実行時間 | 未キャッシュの対象をまとめて判定する1回につき250ms |
| ルール全体の時間予算 | 1回の判定で500ms。各ルールの開始前に超過を確認 |
| 命令数 | 1ルールの実行で2,000,000命令を目安に制限 |
| インタプリタのスタック深さ | 最大128 |

ルールの構文エラー、不正な戻り値、実行上限超過などが起きた場合、そのルールの該当判定をNGにしません。他のルールは引き続き判定し、次のルール開始前に全体の時間予算超過を検出した場合は、その回の高度なNG判定全体をNGなしとして扱います。標準NGによる結果は残ります。

エラー内容は高度なNG画面の状態表示で確認できます。エラーになったルールは修正して保存し直すと再試行します。

同じ入力の判定結果はキャッシュします。呼び出し回数、グローバル変数、前のレスで保存した状態に依存するスクリプトは安定した動作を保証しません。各レス・スレを引数だけで判定する関数にしてください。

## 7. 標準NG・アンカー連鎖との関係

高度なNGスクリプトに渡すのは、判定対象自身の情報です。次の情報・操作を扱うAPIはありません。

- 標準NGWord／NGIDの登録一覧や、各レスの標準NG判定結果の取得。
- アンカー先のレス本文、投稿者ID、NG状態の参照。
- スレ全体のレス一覧を引数から取得してたどる処理。
- スクリプトから標準NGIDへ登録する操作。

本文中の `>>123` を文字列として判定することはできますが、123番のNG状態を調べることはできません。高度なNGに一致しただけで、標準NGWordの「連鎖」「投稿者のIDもNG」の設定が付与されるわけではありません。

### 投稿者IDへ広がったNGの連鎖（今回追加）

標準NGWordの**同じルール**で「連鎖」と「投稿者のIDもNG」を両方ONにした場合、NGWordに一致した投稿者の別レスも連鎖の起点にします。高度なNGの全体スイッチをONにしたり、スクリプトを追加したりする必要はありません。

例: 10番がNGWordに一致するID=Aのレス、20番が同じID=Aの別レス、30番が別人の `>>20` への返信なら、20番を起点として30番にも連鎖NGが適用されます。その後の孫返信もChMateの連鎖処理に従います。

両方のチェックを別々のルールに分けた場合、無効・強調・レス番号指定のルール、IDなし・システム投稿は、この追加処理の対象外です。標準NGIDの保存一覧やDATを書き換える機能ではありません。

詳しい動作と確認範囲は[投稿者IDへ広がったNGの返信連鎖](poster-id-chain-ng.md)を参照してください。この追加処理はローカル実装・ビルド確認済みで、端末上の表示操作は未確認です。公開済みとしては扱いません。

## 9. バックアップと復元

ローカル／MEGAバックアップで「NG設定（高度なNGルールを含む）」を選ぶと、判定式、条件名、対象、対象板、各ルールの有効／無効、全体の有効／無効を保存します。「ChMate・Haiagaruの設定」を選んだバックアップにも保存します。復元後はChMateを再起動してください。

双方向同期は既存の設定値を優先し、複数端末のルール一覧を自動で統合するものではありません。MEGAを使う場合はバックアップファイルを外部へ保存しますが、通常のNG判定は端末内で行います。

過去のバックアップ検証（2026-10-17）では、191のエミュレータ上の分離した検証用データで保存・復元等11項目を確認しています。MEGAサーバーへの実通信は、その検証に含まれていません。

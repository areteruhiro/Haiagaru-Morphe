# Talkのあぼーん・レス参照が開かない問題

Mi Note 10の242 dev・スマホ表示で再現。長押しコピーはオフ、対象ヘッダーと本文の文字選択もオフだった。
タップは `toggleNG` まで届き、ChMateのレスポップアップも生成されていたが、親のポップアップスタック
`o.zzbhn` が `GONE`、レイアウト幅・高さ0になっていた。

Talkの広告余白削除が、起動時に子がない大きなViewGroupを余白と判定し、この領域も削除していた。
FridaでスタックをVISIBLE・MATCH_PARENTへ戻すと、既にタップしたNGレス本文がその場で表示された。

`AdContainerSafety` で、`mActivePopup` を持つレスポップアップスタックとその派生クラスを画面領域として保護する。
既存の余白走査・広告親領域の縮小・空判定・最終縮小のすべてで同じ保護が有効になる。
NG登録や長押しコピー設定を変更する必要はない。

修正済みAPKを入れる前から領域が縮小している場合は、アプリを再起動して画面を作り直す。

## 初回取得後の進む履歴

242の動的コード `getAdChoicesView.a(Activity)` は、画面のIntentをコピーして
`setResult(RESULT_CANCELED, intent)` に保存する。呼び出し元はそのIntentを `forwardIntent` として
「進む」に使う。初回DATインポートは、この初期化より先に元画面を終了する経路を持つ。
Talkの初回インポートが画面を終了する直前に同じresultを設定し、標準履歴への通知を補完する。
取得済みDAT・通常のスレ起動・タブレットのその場で開く処理は変更しない。
